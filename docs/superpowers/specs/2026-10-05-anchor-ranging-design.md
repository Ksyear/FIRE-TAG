# 앵커 간 UWB 거리로 좌표 설정

Tag 이동으로 앵커 좌표를 추정하는 대신 A0–A1, A0–A2, A1–A2를 직접 DS-TWR로 측정합니다. Tag의 기존 UWB 프레임과 경보 기능은 유지합니다. 모든 앵커 펌웨어를 갱신해야 하며, USB 연결과 사용자의 업로드 확인 후 실기 시험합니다.

- Pi는 `CMD <id> <initiator> range <peer>`를 한 번에 하나씩 보냅니다. 명령 ACK는 접수 확인이며 거리 측정 성공과 구분합니다.
- 앵커 측정은 별도 POLL/RESP/FINAL 함수 코드 `0x31/0x32/0x33`과 실제 앵커 주소를 사용합니다. 대상 앵커가 거리를 계산해 기존 ESP-NOW `Report`의 신규 type 4로 전달합니다. `tagId`는 이 type에서만 요청 앵커 번호입니다.
- Anchor 0은 `{"type":"anchor_range","anchor":1,"peer":0,"seq":123,"range_mm":3000,...}` 형식으로 USB에 출력합니다. 기존 거리·상태·경보 JSON은 유지합니다.
- Pi는 세 쌍마다 최근 측정 20개 이상을 모읍니다. 알려진 높이 차이를 반영하고, 중앙값과 산포를 검사합니다. 삼각 부등식과 최소 높이 0.2 m를 통과한 삼각형만 적용합니다.
- 상대 좌표는 A0=(0,0), A1은 +X, A2는 +Y입니다. 방의 절대 위치·방향은 이 측정만으로 알 수 없습니다. 기본 높이와 안테나 지연은 보정 전입니다.
- `calibration_mode=anchor_ranges`를 명시한 설정에만 적용합니다. 기존 Tag 이동 추정 모드는 호환을 위해 유지합니다. 불완전하거나 부정확한 측정으로 좌표를 표시하지 않습니다.
- USB 식별자가 동일한 보드가 여러 대여도 게이트웨이 포트를 지정할 수 있어야 합니다. 시리얼 권한과 수신기 시작 실패를 숨기지 않습니다.
- 새 외부 런타임 의존성은 추가하지 않습니다. Python 표준 라이브러리와 기존 DW3000 드라이버를 사용합니다.

검증: 삼각형 복원·누락·잡음·높이 차이 Python 테스트, 기존 Tag 및 앵커 0/1/2 컴파일, USB 포트별 보드 식별, 세 쌍 실측, Pi 전체 점검 ACK, 실제 위치 갱신 및 영상 기록. 실기에서 아직 확인하지 않은 부분은 보고서와 PR에서 구분합니다.
