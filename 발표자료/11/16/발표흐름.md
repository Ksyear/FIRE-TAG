## 코드 화면을 보여주는 방법

- 본편 7장에 실제 `fire_tag_receiver.py`의 `flush()` 일부만 표시. `solve_position`과 `self.store.position` 두 호출을 중심으로 설명.
- 코드는 편집 가능한 PPT 텍스트. 캡처 이미지로 만들지 않았고, 읽기 쉽게 줄바꿈과 생략 주석만 추가.
- 입력은 교정된 앵커 좌표와 앵커별 거리(m). 출력은 x·y 좌표와 DB의 최근 좌표 갱신.
- 코드 앞의 거리 개수 확인·앵커 교정 완료 검사, 중간 상태 갱신·로그는 발췌 화면에서 생략. 원본 실행 코드의 검사를 삭제한 것이 아님.
- `rms`는 거리 잔차이며 실제 기준 위치에 대한 위치 오차로 발표하지 않음.
- 전체 IDE, 긴 수식 구현, 경량 UI에 없는 명령·경보 코드는 본편에서 설명하지 않음.
- 부록 11장은 `run_dev.sh`의 매 시작 재교정 설정과 마지막 시험의 앵커 거리 표. 재배치 질문에 사용.

## 영상 시연 순서

1. 본편 8장에서 위치 점, 앵커 상태, 최근 이벤트 10개를 먼저 짚습니다.
2. 9장으로 넘겨 영상이 실제 Pi 접속 기록임을 한 문장으로 말합니다.
3. PPT에 포함한 영상을 클릭해 41.56초 재생합니다. 재생 중에는 점이 갱신되는 모습을 보게 둡니다.
4. 영상이 끝나면 잠시 멈추고 10장의 결과로 넘어갑니다.
5. 재생 문제가 있으면 [원본 MP4](경량버전/Pi_경량UI_실제접속시험.mp4)를 별도로 엽니다. PDF는 영상 재생용이 아닌 정지 화면 백업입니다.

실시간 Pi 접속을 필수 시연 경로로 잡지 않았습니다. 하드웨어를 함께 시연할 경우 발표 당일 같은 네트워크에서 Pi 주소와 서버 실행 상태를 확인해야 합니다. 시험 당시 주소를 현재 접속 가능한 주소로 보장하지 않습니다.

## 시험 전 확인할 것

- 매 시험마다 A0·A1·A2 번호, 고정 배치, 세 쌍 상호 거리를 확인합니다.
- A1·A2 위치가 바뀌면 새 배치에서 교정 완료 후 Tag 이동 시험을 시작합니다.
- 실행 중 앵커를 옮겼다면 재시작해 다시 교정합니다.
- 마지막 시험 기록: A0–A1 6.89 m, A0–A2 6.57 m, A1–A2 3.47 m, 교정 샘플 89개.
- 반복 측정 산포 약 8 cm는 실제 위치 정확도 8 cm를 뜻하지 않습니다.
