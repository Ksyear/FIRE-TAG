## 1. Pi 수신부터 경량 화면까지 연결 · 예상 30초

- 화면에서 짚을 곳: 지난 발표와 이번 발표의 범위 비교

지난 발표에서는 **UWB(유더블유비, 초광대역 무선)** 모듈을 **ESP32(이에스피삼십이)**에 연결하고 통신을 확인했습니다.
이번에는 앵커가 측정한 값을 **Raspberry Pi(라즈베리파이)**로 전달했습니다. Pi에 저장한 좌표를 경량 웹 화면에서 확인하는 단계까지 구성했습니다.
전체 연결 구조를 설명한 뒤 실제 코드와 동작 영상을 보여드리겠습니다.

- 근거: 경량버전/11월16일_발표자료.md, 1~4절

## 2. 실내 장치 구성 · 예상 35초

- 화면에서 짚을 곳: 아래 Tag, 양옆 앵커, 위쪽 A0와 Pi 순서

먼저 전체 장치 구성입니다.
이동하는 장치는 **Tag(태그)** 한 대입니다. 고정 장치는 **A0(에이제로)**, **A1(에이원)**, **A2(에이투)** 세 대입니다.
Tag와 앵커가 거리를 측정합니다. A0가 각 앵커의 보고를 모아 Pi로 전달합니다.
그림은 연결 관계를 설명하기 위한 예시입니다. 실제 위치 계산에는 시험 전에 교정한 앵커 좌표를 사용했습니다.
(쉼)

- 근거: firmware/fire_tag_tag/fire_tag_tag.ino:1, firmware/fire_tag_anchor/fire_tag_anchor.ino:1

## 3. Pi와 A0 연결 · 예상 30초

- 화면에서 짚을 곳: Pi와 A0 사이의 하늘색 USB 케이블

이제 중앙의 유선 연결부터 보겠습니다.
Pi의 **USB(유에스비)** 포트와 A0 ESP32를 케이블로 연결했습니다. 이때 A0가 **USB 시리얼(시리얼 통신)**로 측정 보고를 보냅니다.
A1과 A2의 보고도 A0를 거쳐 이 연결로 들어옵니다. 그래서 Pi에서는 A0에 연결된 시리얼 포트를 읽도록 구성했습니다.
다음은 거리값을 얻는 과정입니다.
(쉼)

- 근거: firmware/fire_tag_anchor/fire_tag_anchor.ino:3, raspberrypi/fire_tag_receiver.py:246

## 4. Tag와 앵커 거리 측정 · 예상 35초

- 화면에서 짚을 곳: Tag와 세 앵커 사이의 양방향 UWB 화살표

유선 연결에 앞서, 거리값은 여기서 만들어집니다.
Tag가 앵커에 요청을 보냅니다. 앵커가 응답하면 Tag가 마지막 메시지를 보냅니다.
그림의 **POLL(폴)**, **RESP(알이에스피)**, **FINAL(파이널)** 순서입니다. 앵커는 이 교환에서 얻은 시간 정보로 거리를 계산합니다.
Tag가 세 앵커와 이 과정을 반복합니다. 각 앵커까지의 거리값을 모아 다음 단계로 전달합니다.
(쉼)

- 근거: firmware/fire_tag_tag/fire_tag_tag.ino:3, firmware/fire_tag_anchor/fire_tag_anchor.ino:3

## 5. A1·A2 보고를 A0로 전달 · 예상 35초

- 화면에서 짚을 곳: A1·A2에서 A0로 들어오는 점선 화살표

측정한 거리값은 A0에 모읍니다.
A1과 A2는 **ESP-NOW(이에스피나우)**로 A0에 측정 보고를 보냅니다. A0는 자신의 측정값도 함께 모읍니다.
여기서 UWB는 거리 측정에 쓰고, ESP-NOW는 앵커 사이의 보고 전달에 씁니다.
Pi가 ESP-NOW 보고를 직접 받는 구조는 아닙니다. Pi에는 A0가 USB로 전달합니다.
(쉼)

- 근거: firmware/fire_tag_anchor/fire_tag_anchor.ino:3~7

## 6. Pi에서 위치 계산·화면 표시 · 예상 35초

- 화면에서 짚을 곳: USB 보고 방향과 하단 처리 순서

A0가 보낸 보고를 Pi에서 처리합니다.
수신기는 교정된 앵커 좌표와 Tag 거리값으로 평면 위치를 계산합니다. 계산한 좌표는 **SQLite(에스큐엘라이트)** 데이터베이스에 저장합니다.
경량 웹 서버는 저장된 값을 읽어서 화면에 제공합니다. 같은 **Wi-Fi(와이파이)**의 Mac이나 휴대폰에서 Pi에 접속합니다.
다음 화면에서는 이 처리 중 계산과 저장 부분을 실제 코드로 보겠습니다.
(쉼)

- 근거: raspberrypi/fire_tag_receiver.py:443, raspberrypi/fire_tag_web_lite.py:1

## 7. 거리값을 좌표로 계산해 저장 · 예상 45초

- 화면에서 짚을 곳: solve_position 호출, 실패 시 return, self.store.position 호출

앞에서 설명한 계산과 저장을 담당하는 코드입니다.
먼저 위쪽의 **solve_position(솔브 포지션)**을 보시면, 앵커 좌표와 거리값을 넣어 위치를 구합니다. 계산할 수 없으면 여기서 처리를 멈춥니다.
계산이 끝나면 **x, y(엑스, 와이)** 좌표를 얻습니다. 아래의 **store.position(스토어 포지션)**이 결과를 데이터베이스에 저장합니다.
그 전에 세 앵커의 거리 수집과 교정 완료를 검사합니다. 화면에는 핵심 부분만 발췌했습니다.
(쉼)

- 근거: raspberrypi/fire_tag_receiver.py:443~476, Store.position:114~119

## 12. 당김식 전원 스위치 구상 (선택 부록) · 예상 30초

- 화면에서 짚을 곳: 왼쪽 핀 삽입 OFF, 오른쪽 핀 제거 ON

이 부분은 추가 제작 구상입니다.
절연핀이 레버를 누를 때는 **COM–NC(콤, 엔씨)** 접점이 열려 배터리 전원이 꺼집니다. 핀을 빼면 레버가 복귀하고 접점이 연결돼 켜진 상태를 유지합니다.
실물 제작과 동작 시험은 아직 하지 않았습니다. 이번 경량 UI 구현 결과와는 구분합니다.
